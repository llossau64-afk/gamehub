# ASCEND architecture

## Principles

1. **Offline-first.** The on-device Zustand store, persisted with AsyncStorage, is the source of truth. Every feature works without a network connection. Cloud sync is an add-on.
2. **Deterministic safety around AI.** The AI suggests and the domain layer decides. Plans from any source go through `validatePlan`. Chat answers come with a safety system prompt on the server and an offline fallback that only uses the player's own data.
3. **Pure domain logic.** Everything in `src/domain` is framework-free TypeScript with unit tests. The screens are thin.
4. **No fake data.** Charts only show recorded sessions. Sample data exists only in Demo Mode, is generated from the plan at render time, and every screen that shows it carries a label.

## Data flow

```
UI (src/app) ──actions──▶ store (src/store/useAppStore.ts) ──persist──▶ AsyncStorage
                              │  resolveProgress(): XP → level/rank → achievements → missions → celebrations
                              │
                              └── sync.dirty ──▶ services/sync.ts ──▶ Supabase (RLS)
```

- `finishWorkout()` builds the session and detects PRs against the player's own history. It then computes XP with the anti-farming rules and runs `resolveProgress()`, which queues level-up, rank-promotion and achievement celebrations. The `CelebrationOverlay` in the root layout plays them.
- `submitFeedback()` calls `applyFeedback()`, which can swap exercises away from a painful area, shorten or ease a day, or add a set. It then re-validates. The changes go into `planChanges`, shown as *Coach updates* in the Train tab.
- The active workout lives in the persisted store. That means the coach modal, the technique guide, and even killing the app never lose progress.

## Sync

`services/sync.ts` pushes rows changed since `lastSyncedAt`, deletes removed rows, and the XP ledger is append-only. On sign-in and app start it pulls the remote rows and merges them with `mergeState` (union by id, newest `updatedAt` wins). Sync is debounced by 4 s after local changes and runs again when the connection comes back (NetInfo).

## Auth

- **Guests:** with a backend configured, they get an *anonymous* Supabase session, so the AI coach and backup work under RLS. Without a backend they stay purely local.
- **Account creation** upgrades the anonymous user in place with `updateUser({ email, password })`, so the user id and history are kept.
- **Sessions** are stored in the iOS Keychain or Android Keystore through `expo-secure-store`, split into chunks because SecureStore limits each value to about 2 KB. Tokens only refresh while the app is in the foreground.
- **Password reset** uses a 6-digit email code (`verifyOtp` with type `recovery`). This avoids fragile deep links.
- **Account deletion** goes through the `delete-account` Edge Function, which holds the service role. All tables cascade.

## Plan engine

| Module | Role |
|---|---|
| `plan/library.ts` | Filters exercises by equipment, limitations and difficulty. Finds a safe substitute: listed alternatives first, then the same movement pattern, then the same category. |
| `plan/generator.ts` | Picks a split by number of training days (Full Body, Upper/Lower, U/L + PPL, or PPL×2). Fills template slots by movement pattern. Applies the goal's rep scheme and the experience and age modifiers. Fits sessions to the time budget. Caps weekly volume. Falls back to full-body sessions when equipment is very limited. |
| `plan/validator.ts` | Repairs or rejects any plan (see the README for the list of checks). |
| `plan/progression.ts` | Double-progression suggestions, deloads, pain-aware reductions, and feedback adaptation. |

## XP & progression

`domain/xp.ts` holds the rules. `domain/ranks.ts` defines the level curve: `150 + 50·(level−1)` XP per level, with rank thresholds E1, D10, C20, B35, A50, S70 and SS100. `domain/quests.ts` derives quest state from the XP ledger, so there is no separate quest state to drift out of sync. `domain/achievements.ts` covers achievements and flexible streaks: planned rest days count, one missed training day per rolling week is forgiven, and nothing is ever deducted.

## Audio & motion

The sound effects are generated by `scripts/generate-sounds.mjs`. They are original synthesis, with no third-party audio. Sound, music, haptics and motion can each be switched off. `useReduceMotion()` combines the system setting with the in-app override, and every animated component checks it.
